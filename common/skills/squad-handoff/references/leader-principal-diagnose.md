# リーダーの手順: 診断を頼む

このファイルはリーダーの手順で、リーダーだけが読む。リーダーの指示の「場面と手順」から、最上位の役に診断を頼むときに読む。前の実行で読んだ記憶で済ませず、その実行の中で読む。

最上位の役がないときは、このファイルを使わない。最上位の役の有無と系統で分かれる手順は、場合分けで書く。どの場合かは、リーダーの指示の「このスクワッドの役」で決まる。

## 診断を頼む

**診断**: 先頭で、[leader-repeat.md](leader-repeat.md) の「診断に入る条件」を確認する。リーダーの指示の原則 7 に最上位の役の診断がないとき、または最上位の役がないときは、この手順を使わず、頼み直すか人間を呼ぶ。数え方と、診断に回さない止まり方、診断の上限は、[leader-repeat.md](leader-repeat.md) の「同じ誤りや差し戻しが続くとき」にある。

最上位の役は `squad-usage-wait pick <タスク> principal` で選び、標準出力をファイルに保存する。診断は実装の系統と関係がないので、系統は渡さない。時間切れは 120 秒以上にする。終了 0 のときに保存したファイルを使い、ほかの終了コードは下のとおりに扱う。

- 終了 3 では、続いた失敗と `使用率の待ち:` の行をタスクのコメントに写して終える。数え方の行は置かない。待ちの起こしで起きたら、同じ失敗を読み直して判断する。待つ間に `数え直し:` の行が置かれていれば、頼まない
- 終了 4 と 1 では、続いた失敗と原因を添えて人間を呼ぶ。使用率が上限に近いことだけを理由に診断を飛ばさない

続いた失敗の根拠を別のファイルに書く。同じ誤りなら、最初の失敗と再発のそれぞれの出どころと根拠、書いた原因、頼んだ直し方を入れる。同じ部品なら、3 回の指摘と、2 回目の種類単位の範囲と修正の役が書いた表の場所を入れる。

依頼は `squad-review-next diagnose` で置く。制御の行はスクリプトが組み、根拠は囲みに入れる。見張りの登録とコメントの投稿もスクリプトが行う。

- 診断の依頼には、`修正の依頼:`・`同じ誤り:`・`同じ部品:` の行を置かない。診断のあとの修正の依頼に置く（[leader-repeat.md](leader-repeat.md) の「数え方の行」）

```text
squad-review-next diagnose <タスク> <きっかけのコメント> <確認するコミット> <pick の出力のファイル> <根拠のファイル> --times <N> --failure <同じ誤り | 同じ部品> <対象> [--failure …] [--human-design]
```

確認するコミットは完全な SHA にする。PR がまだなければ、作業ブランチの head を使う。回数は [leader-repeat.md](leader-repeat.md) の「数え方の行」で数え、同じ回に失敗が重なれば失敗ごとに `--failure` を渡す。空白を含む値は引用して 1 引数にする。

設計の役がなければ `--human-design` を付ける。設計と PR の見直しを重ねる場合は [leader-principal-design.md](leader-principal-design.md) の「手戻りの見直しと重なるとき」に従う。終了 0 なら `依頼:` の行で投稿を確認する。終了 1 か 2 なら、出力と続いた失敗を添えて人間を呼ぶ。

- 診断の回の返事は、`decide` が次の依頼を決めず、`次の依頼を決められません: 診断の回はリーダーが扱う` でリーダーを起こす。結果の `診断:` と `直す役:` の行を読んで扱う。`decide` は、診断の回の結果を設計と PR の見直しの結果に数えない。重要のマークのあるタスクで診断だけが返っても、設計と PR の見直しを済んだとしない
- `直す役: 修正の役` なら、返った直し方を修正の依頼として、修正の役へ 1 回だけ頼む。`直す役: 設計の役` なら、設計の変更として設計の役へ頼む。設計の役がない構成では、`leader-principal-design.md` の「設計の役がない構成の設計の直し」に従い、人間に設計の変更と承認し直しを頼む
- 設計の役が直した設計を人間が承認し直したら、実装の役へ、承認し直した設計の実装を頼む。実装の役は、`leader-dispatch.md` の「役の選び方」のとおり、`squad-usage-wait pick <タスク> implement` で選ぶ。フェーズの依頼ではないので、見積もりの語（`小さい`・`大きい`）は添えない。依頼は、実装の役をメンションし、承認し直した設計にコードを合わせる実装を、同じ PR のブランチに積むよう頼む。依頼には、診断の結果へのリンクと、検証待ちの失敗を添える。同じコメントに `数え直し: 同じ誤りのすべて。理由: 設計の承認し直し` を置き、診断した失敗は検証待ちのまま残す。この依頼は修正の依頼ではないので、`修正の依頼:`・`同じ誤り:`・`同じ部品:` の行は置かず、修正の依頼に数えない。設計の文書は設計の役が直したので、実装の役には直させない。設計の役と修正の役は呼ばない
- `診断: 人間の判断が要る` か `直す役: なし` なら、診断を添えて人間を呼び、`in_review` にする
- `診断:` か `直す役:` の行のない結果、実行の失敗、`確認したコミット:` の 2 回続けての食い違いは、診断が返らなかったものとして、頼み直さずに人間を呼ぶ。続いた失敗と原因を添える
- 診断のあとの再発と検証待ちの扱いは、[leader-repeat.md](leader-repeat.md) に従う
