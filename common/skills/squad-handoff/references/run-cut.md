# 実行の区切りの手順

このファイルは、区切りを使う役（Claude の実装の役・修正の役・設計の役）が、作業の区切りに来たときと、区切りの続きで起きたときに読む。

## 実行の区切り

長い実行は、作業の区切りで引き継ぎのコメントを書き、同じ役の続きの実行に渡して終える。続きが始まればリーダーは挟まず、始まらないか失敗したときだけリーダーが起きる。区切る基準の値は `squad-run-cut` が持つので、役は値を書かず、比べもしない。

### 区切るかを決める

作業の区切りに来るたびに、次を流す。作業の区切りの途中では流さない。

```bash
squad-run-cut check <タスク> <自分のエージェントの ID> <圧縮の回数>
```

出力は `区切り: <要る | 要らない> 呼び出し=<数> 圧縮=<数>` の 1 行である。`要らない` なら、そのまま作業を続ける。

| 作業の区切り | 役 |
| --- | --- |
| テストと lint が通る状態でコミットを push したあと | 実装の役 |
| 1 件の指摘の直しを push したあと | 修正の役 |
| 設計の文書の節を push したあと。draft PR がまだなければ、作ったあと | 設計の役 |

圧縮の回数は、次の順で数える。圧縮のたびに、今の回数を `tmp/run-cut-compactions-<実行の ID>` に書く。実行の ID は環境変数 `MULTICA_TASK_ID` である。

1. ファイルがあれば、その数に 1 を足す
2. ファイルがなく、受け取った「前の会話の要約」に前の回数が書いてあれば、それに 1 を足す
3. どちらもなければ、要約を受け取っていれば 1、受け取っていなければ 0 にする

`check` が終了コード 1 で終わったときは、値を読めていない。区切らずに作業を続け、最後の引き継ぎに `check` の出力と終了コードを書く。終了コード 2 は使い方の誤りなので、引数を直して流し直す。

### 区切るとき

`区切り: 要る` なら、次の 4 行のファイルを `tmp/` に書く。どの行も、行の頭から始め、中身を空にしない。

```text
区切り: <続けて区切った回数> 回目
済んだこと: <push したコミットと、終えた作業>
残り: <残っている作業>
次に読む場所: <ファイルと節、コメント、PR のコメント>
```

続けて区切った回数は、スクリプトが数え直すので、見込みの値でよい。ファイルを渡して投稿する。

```bash
squad-run-cut post <タスク> <ファイル> <自分のエージェントの ID> <リーダーのエージェントの ID>
```

終了コード 0 なら、`投稿:`・`見張り:`・`起こし:` の 3 行が出る。区切りのコメントは、リーダーもスクワッドもメンションしない。投稿のあと、作業を止めて実行を終える。通常の引き継ぎは書かない。

| 終了コード | 意味 | すること |
| --- | --- | --- |
| 0 | 投稿して、見張りと続きの起こしを作った | 実行を終える |
| 1 | 値のファイルの誤りか、コメントの読み書きの失敗。投稿も起こしもない | 通常の引き継ぎでリーダーへ返し、区切れなかったことを書く |
| 2 | 4 行のどれかがないか空、または使い方の誤り | 行か引数を直して流し直す |
| 3 | 起こしを作れない | 通常の引き継ぎでリーダーへ返し、起こしを作れなかったことを書く |
| 4 | 続けて区切れる回数を超えた。投稿も起こしもない | 通常の引き継ぎでリーダーへ返す |

### 区切りの続きで起きたとき

指示が `区切りの続きで起きました。` で始まる実行は、作業の前に、指示の区切りのコメントの ID で次を流す。

```bash
squad-run-cut resume <タスク> <区切りのコメントの ID> <自分のエージェントの ID> <リーダーのエージェントの ID>
```

終了コード 0 なら `続き: <区切りのコメントの ID>` が出る。リーダーの依頼は読み直さず、区切りのコメントの「次に読む場所」から作業を続ける。続きの実行も、作業の区切りに来るたびに、同じ手順で `check` を流す。最後に作業を終えた実行が、通常の引き継ぎでリーダーへ返す。

終了コード 1（コメントを読めない、作者が自分でない、`区切り:` の行がない）と 3（見張りを作れない）は、作業を続けず、通常の引き継ぎでリーダーへ返し、続けなかった理由を書く。終了コード 2 は使い方の誤りなので、引数を直して流し直す。
