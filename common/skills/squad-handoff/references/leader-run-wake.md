# リーダーの手順: PR のあるタスクで起きたときの確認

このファイルはリーダーの手順で、リーダーだけが読む。リーダーの指示の「場面と手順」から、PR のあるタスクで、ほかのきっかけで起きたときに読む。前の実行で読んだ記憶で済ませず、その実行の中で読む。タスクとコメントの読み直しは `squad-task-read <タスク>` を使う。

## 起きたときの確認

PR のあるタスクで起きたときは、きっかけを問わず、返事を待つ回の途中でない限り、動いている実行の長さを確認する。進捗を聞かれていなくても確認する。コンフリクトの状態の確認は、`leader-pr-ci.md` の「起きたときの確認」にあり、この確認の結果をその手順へ渡す。

1. `leader-run-status.md` の「実行の状態を確認して答える」の 1 と 2 のとおり、`multica issue runs <タスク> --active --output json` を流し、自分の実行を除く。親か子があるときは `--siblings` も流す
2. 残った実行のうち、その PR に触れる実行があるかを読む。実装・修正の役の実行は、触れるものとして数える。役が分からない実行も、触れるものとして数える。重ねて呼ぶ方に倒さないためである。この結果は `leader-pr-ci.md` の条件に使う
3. `started_at` から 45 分を超えて動いている実行があれば、その実行の記録を `multica issue run-messages <実行の ID> --issue <タスク> --output json` で、末尾の数件読む

`squad-run-cut state <タスク>` が `待ち` か `動いている` を返す役は、動いている実行がなくても、その PR に触れる役として数える。`leader-run-cut.md` の「区切りの途中」に従う。

45 分を超えて動いている実行は、同じ実行につき 1 回だけ人間に知らせる。知らせる前に、タスクの前のコメントに、同じ実行の ID の `実行の遅れ:` の行があるかを確認する。あれば、もう知らせない。起きるたびに同じ知らせを繰り返さないためである。

知らせるコメントには、`実行の遅れ: <実行の ID>` の行を置く。あわせて、`leader-run-status.md` の「実行の状態を確認して答える」の 5 項目と、記録の要約、読めなかったものは「未確認」と書く。呼ぶ人間をメンションし、実行を止めるかどうかは人間が決めると書く。止めた方がよいと考えたときは、`leader-run-stop.md` の「実行を止める」の提案に従う。

知らせても、実行は止めない。タスクの状態も変えない。45 分を超えていない実行は、知らせない。
