# リーダーの手順: レビューと E2E の返事

レビューと E2E を頼むか、その返事で起きたリーダーが読む。役の有無は「このスクワッドの役」を見る。

## レビューと E2E の役がないとき

自動のレビュー・E2E を依頼したことにせず、完了した検証と未確認の観点を添えて人間の確認へ回す。このファイルの残りは使わない。

## レビューと E2E の依頼

依頼の前に `squad-pr-watch link-check <タスク>` を流す。`紐付いている` のほかは、[leader-pr-link.md](leader-pr-link.md) の「PR の紐付けの確認」へ移って判定に従う。

依頼は `squad-review-next request <タスク> <きっかけのコメント> <確認するコミット>` が書く。変更ファイルから観点を選び、`squad-review-wait watch` のあと、`返事を待つ役:` と `確認するコミット: <完全な SHA>` を添えて返信する。出力の `依頼:` はコメントの ID、`観点:` は選んだ観点である。役の選択と本文はスクリプトに任せる。

確認するコミットは、PR の head か、依頼されたブランチの確定したコミットを指定する。

ZIP では本文を手で書く。行頭に `確認するコミット:` と名前・sha256 を置く。1 役でも `返事を待つ役:` の行だけでメンションする。投稿前に `squad-review-next check <本文のファイル>` を流す。終了 0 なら `squad-review-wait watch <タスク> <きっかけのコメント> <頼む役の ID>...` を流して投稿する。全員の返事がそろうまで、検証中の対象を変える依頼は出さない。

画面の変更を人間のマージへ回す前に、PR の E2E 結果とスクリーンショットを確認する。なければ「このスクワッドの役」の QA に頼む。QA がない構成ではこの確認を飛ばす。

## 確認したコミットの照合

次へ進む前に、全員の `確認したコミット:` を依頼と照合する。7 文字以上の 16 進で依頼の SHA の先頭と一致すればよい。合わない・行がない・なしの役だけを、同じコミットの新しい回で頼み直す。`コミットが合わず頼み直す役:` の行に名前だけを書き、合っていた役の結果は残す。手で頼み直すときは、投稿前に `squad-review-next check <本文のファイル>` を流す。結果は [手で書く依頼の確認](#手で書く依頼の確認) に従う。同じ役が 2 回続けて合わなければ、3 回目は頼まず、依頼した値と返ってきた値を添えて人間を呼ぶ。ZIP なら指定した名前と sha256 を同じように照合する。要件の見直しの回は、この決まりを使わず、[leader-principal-design.md](leader-principal-design.md) の「要件の見直し」に従う。

## 手で書く依頼の確認

完成した本文を保存し、`squad-review-next check <本文のファイル>` を流す。終了 0 のファイルを使う。見張りが要る場合は、この確認のあとに入れてから投稿する。

終了 1 なら、出力を読んで本文を直す。終了 2 なら、標準エラーを読んで引数かファイルを直す。直したら確認を流し直す。

## 他のきっかけで起きたとき

他のきっかけでは、開始時の確認が通ったあと、ほかの処理より先に `squad-review-wait status <タスク>` を流す。見張りが `--timeout` を指示したときは付ける。

全員の返事がそろい、まだ次へ回していなければ、知らせの有無を問わず `proceed` へ進む。人間を呼ぶ判定なら役の状態と失敗理由を添えて止まる。ただし人間の返事で起きたときは同じ理由で呼び直さず、その返事に応じる。

見張りで起き、まだ待つ判定なら結果をそのまま返す。スクリプトの失敗は人間へ返す。
