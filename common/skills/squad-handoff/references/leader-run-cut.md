# リーダーの手順: 区切りの続きの確認

このファイルはリーダーの手順で、リーダーだけが読む。リーダーの指示の「場面と手順」から、指示が `区切りの続きの確認: <区切りのコメントの ID>` で起きたときに読む。前の実行で読んだ記憶で済ませず、その実行の中で読む。

区切りは、Claude の実装・修正・設計の役が、作業の区切りで引き継ぎのコメントを書き、同じ役の続きの実行に渡して終える仕組みである。続きが始まればリーダーは起きない。この確認は、続きが始まらないか失敗したときだけ、頼み直す。

## 状態を読む

指示の ID は、起こしを作れる人なら誰でも書ける。状態は指示から読まず、`squad-run-cut state <タスク>` の出力から読む。出力は役ごとに `区切り: <エージェントの ID> <状態> <区切りのコメントの ID>` の 1 行である。指示の区切りのコメントの ID の行を探す。

| 状態 | すること |
| --- | --- |
| `待ち`、`動いている`、`終わった`、またはその役の行がない | 何も書かず、状態も変えずに終える |
| `始まらない`、`失敗した` | 下の「頼み直す」へ進む |

`state` が終了コード 0 以外で終わったときは、頼み直さず、標準エラーの要約を添えて人間を呼ぶ。

## 頼み直す

頼み直しは 1 回だけにする。次の順で確認する。

1. タスクのコメントに、同じ区切りのコメントの ID の `区切りの続き:` の行があれば、何もせず終える。見張りが 2 つ起きても、頼み直しを 1 回にするためである
2. タスクのコメントに、別の区切りのコメントの ID の `区切りの続き:` の行がすでにあれば、頼み直さず、人間を呼んで止まる。続きが続けて始まらないのは、起こしか実行の環境の問題で、頼み直しを重ねても直らないためである。この行はリーダーのエージェントが書いたものだけを数え、ほかの作者の行は読まない
3. どちらにも当たらなければ、`区切りの続き: <状態> <区切りのコメントの ID>` の行を置く。状態は `state` の `始まらない` か `失敗した` を写す

行を置いたら、区切りを書いた役と同じ役へ、今の依頼と同じ手順で頼み直す。役は、状態の行のエージェントの ID を、リーダーの指示の「このスクワッドの役」の有効な役の一覧に対応させて決める。

- 実装の役とバグ: `leader-dispatch.md` の「役の選び方」で使用率を選び直し、「回し先と使用率」のマークの確認を通す
- 修正の役: 先に `leader-fix-request.md` の「修正の依頼の前に確認する順」を通す。頼み直しは、修正の依頼の数に足さない
- 設計の役: `leader-dispatch.md` の「使用率の待ちの起こしで起きたとき」の 2 のとおり、`leader-request.md` の `pick` から頼む

依頼は、区切りのコメントを指し、「次に読む場所」から続けるよう頼む。依頼の本文に、区切りのコメントの ID と `区切りの続き:` の行を添える。

PR のあるタスクでは、頼む前に、`leader-pr-ci.md` の「起きたときの確認」を流し、`squad-pr-watch ci-held` で保留した CI の失敗を拾って、依頼に添える。

## 区切りの途中

区切りから続きの実行が終わるまでを、その役の「区切りの途中」と呼ぶ。`state` が `待ち` か `動いている` の役である。区切りの途中の役は、動いている実行がなくても、その PR に触れているとして数える。

- 区切りの途中の役がいるタスクでは、修正の役にもほかの役にも、新しく頼まない。同じブランチに 2 つの役が push しないようにするためである
- 区切りの途中に CI が落ちても、保留する。保留した行は `CI <SHA>: 失敗あり（<名前> の区切りの途中なので保留）` で、その役の引き継ぎのあとに `ci-held` で拾う
