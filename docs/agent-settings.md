# 役の実行の共有の設定と環境変数

役の実行に、人が claude.ai で使うスキルを混ぜず、無人の実行に要らない機能を止める。ホストの共有の設定と、役の環境変数と引数で決める。Codex の役は、設定の検証と、指示を読む量の上限をそろえる。

この文書は、原本を変える人に向けて、設定の中身と理由、実機で確認した結果を書く。使う人への手順は `manual.md` に書く。

## 目的と範囲

役の実行は、エージェント用の Claude Code の設定ディレクトリを全役で共有する。人がログインに使うのも同じディレクトリである。今はキットが設定を書かないので、人の claude.ai のスキルと、無人の実行に要らない機能が役に出る。

ここでは、セットアップの流し直しで次の 4 つを入れる。効く範囲は、置き場によって 2 つに分かれる。

| 入れるもの | 効く範囲 |
| --- | --- |
| Claude Code の共有の `settings.json` に、キットが持つキーを書く | 同じホストのすべてのプロジェクトの役 |
| エージェント用の Codex の `config.toml` に、2 つのキーを足し、厳しい検証にかける | 同じホストのすべてのプロジェクトの役 |
| Claude のモデルの役の custom_env に、3 つの環境変数を足す | 流し直したプロジェクトの役だけ |
| Codex の役の引数に、指示を読む量の上限を足す | 流し直したプロジェクトの役だけ |

`permissions.deny` に書く 3 つの道具は、棚卸しで順 1 とした項目の残りを止めるものである。環境変数では消えない道具だけを止める（[止める道具](#止める道具)）。

次は対象にしない。

- 役ごとに違う設定を `--settings` で渡すこと。Multica が再開の実行にも引数を付けるかを、先に確認する必要がある
- deny によるガード（認証情報のファイルや Bash のコマンドを禁じること）と、フックによる完了の確認。棚卸しの順 2 で、別のステージで扱う
- 役の指示と共通スキルの文。AGENTS.md を読む手順も残す

## Claude Code の共有の設定

キットは、エージェント用の設定ディレクトリの `settings.json` に、決まったキーだけを書く。人が書いたほかのキーは残す。設定ディレクトリの設定は、全役と、続きから始める実行のどちらにも効く。

### 書くキー

次の 8 つのキーを、キットが持つ。値は、実機で効くことを確認したものである。

| キー | 値 | 効くこと |
| --- | --- | --- |
| `syncClaudeAiSkills` | `false` | 人の claude.ai のスキルが、役のスキルの一覧に出ない |
| `syncClaudeAiPlugins` | `false` | 人の claude.ai のプラグインが、役に入らない |
| `pluginConfigs` の `cc-plugin-agents-md@builtin` | `options.instructionFiles` を `claude-md` | AGENTS.md を自動では読み込まない |
| `disableWorkflows` | `true` | Workflow の道具と、それを使う同梱スキルが消える |
| `autoMemoryEnabled` | `false` | 自動メモリを読まず、書かない |
| `cleanupPeriodDays` | `30` | 実行の記録を 30 日残す |
| `skillOverrides` | [止めるスキル](#止めるスキル)の 14 件を `off` | 役が使わない同梱スキルが、一覧から消える |
| `permissions.deny` | `Monitor`、`ScheduleWakeup`、`RemoteTrigger` | 環境変数で消えない、実行の後に残る処理の道具を使えなくする |

`pluginConfigs` の項目の名前は、末尾の `@builtin` まで要る。`cc-plugin-agents-md` や `agents-md` の名前では効かなかった。

### AGENTS.md の読み込み

AGENTS.md の自動の読み込みは入れない。役は、今と同じく、役の指示の手順で checkout の AGENTS.md を読む。承認済みの main の AGENTS.md だけを自動で読む形は、設定だけではできず、フックを足せばできた（[実機で確認した結果](#agentsmd-の読み込みの確認)）。

役の作業ディレクトリには Multica の CLAUDE.md があり、checkout はその下の階層にある。CLAUDE.md があると、Claude Code の既定は AGENTS.md を読まない。キットは `claude-md` の値を書き、Claude Code の既定が変わっても読み込まないようにする。

フックの形をこの変更に入れない理由は、次の 3 つである。

1. 役の指示は、今も checkout の AGENTS.md を読む手順を持つ。フックを入れても、PR の未承認の変更は手順から入るので、書き手の確認なしに採用しない形にならない
2. フックは、ホストの全役のすべての Read で動く新しいスクリプトになる。置き場と配り方、書き換えへの守りは、順 2 のフックとあわせて決める
3. 信頼の根は、手元の `origin/HEAD` の参照である。fetch で動き、同じ OS の利用者が書ける共有の置き場にあるので、承認済みかの確認のしかたを順 2 で決める

役の指示の手順を変えることと、フックの形は、順 2 であわせて扱う（[残る危うさ](#残る危うさ)）。

### 自動メモリと記録の日数

自動メモリは切る。置き場は作業ディレクトリごとで、タスクごとに変わるので、タスクをまたいで残らない。書いた中身を誰も見直さないまま、同じタスクの続きに効くのも避ける。

このホストの共有の置き場には、4,075 の作業ディレクトリの記録があり、中身のあるメモリは 36 だった。切っても、役の動作に頼られている形跡はない。

記録の日数は、既定と同じ 30 日を書く。役は、タスクのコメントを読み直して続きを始めるので、それより古い記録には頼らない。値を書くのは、人の設定や既定が変わっても、役の記録の日数を変えないためである。

### 止めるスキル

同梱スキルのうち、役が使わないものを `skillOverrides` で止める。レビューの役が使うスキルは残す。

| 扱い | スキル | 理由 |
| --- | --- | --- |
| 残す | `code-review`、`simplify`、`security-review` | レビューの役が使う |
| 残す | `claude-api`、`verify`、`run` | 実装と QA の役が、作業先で使うことがある |
| 止める | `batch`・`loop`・`schedule`・`deep-research`・`workflow-authoring` | 多数のエージェントや、実行の後に残る処理を起こす |
| 止める | `design`、`design-sync`、`dataviz` | 人と画面でやりとりする作業に向けたもの |
| 止める | `debug`・`doctor`・`update-config`・`fewer-permission-prompts`・`plugin-authoring`・`run-skill-generator` | Claude Code 自身の設定や拡張を変える |

`security-review` は、スキルの一覧ではなくコマンドの一覧に出る。止める一覧に入れなければ残る。`disableBundledSkills` は使わない。レビューのスキルまで消えるためである。

### 止める道具

`permissions.deny` には、棚卸しの順 1 の項目を環境変数で入れても残る道具だけを書く。どれも、実行の後に処理を残すか、別のエージェントを起こす。

| 道具 | 当たる順 1 の項目 | deny が要る理由 |
| --- | --- | --- |
| `Monitor` | バックグラウンド実行を切る | `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` を付けても残った |
| `ScheduleWakeup` | 使わない重い機能を切る（定期実行） | `CLAUDE_CODE_DISABLE_CRON` を付けても残った |
| `RemoteTrigger` | 使わない重い機能を切る（多数のエージェントを起こす機能） | どちらの変数を付けても残った |

ここでの deny は、機能を止めるために使い、ガードには使わない。認証情報のファイルや Bash のコマンドを禁じる deny は、順 2 で扱う。順 2 の項目を先に取り込むものではない。

### 人の設定と合わせる

`settings.json` は JSON で、管理のマークを書けない。そこで、ほかの共有のファイルのようにファイルごとではなく、キーごとに持ち主を決める。キットが持つキーの一覧は、コードに置く。

- ファイルがなければ、キットのキーだけで作る
- キットが持つキーだけを書く。ほかのキーは、値を変えずに残す
- `pluginConfigs` と `skillOverrides` は、キットの項目だけを置き換え、人の項目を残す
- `permissions.deny` は、人の項目にキットの項目を足す。同じ項目は重ねない
- キットが持つキーに人が別の値を書いていたら、キットの値で上書きし、警告を出す
- 中身が変わらなければ書かない。書くときは、同じディレクトリの一時ファイルから置き換え、権限を 600 にする
- シンボリックリンク、JSON として読めない、最上位がオブジェクトでない、のどれかなら書かずに止まる
- `permissions` か `permissions.deny`、`pluginConfigs` の形が違う（オブジェクトや配列でない）ときも、書かずに止まる

後のバージョンでキーをやめるときは、そのキーを「やめたキー」の一覧に移し、流し直しで消す。項目を足すキー（`permissions.deny` など）は、キットが書いた項目だけを消す。

人がエージェント用のログインをするときも、同じ設定が効く。人のログインの端末にも、止めたスキルと道具は出なくなり、AGENTS.md も自動では読み込まれない。

## Claude のモデルの役の環境変数

設定のキーにない 3 つは、custom_env で渡す。今の `CLAUDE_CONFIG_DIR` などと同じく、Claude のモデルの役にだけ付け、流し直しで付け外しする。

| 変数 | 値 | 効くこと |
| --- | --- | --- |
| `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` | `1` | Bash を裏で動かせなくなり、サブエージェントは終わるまで待つ |
| `CLAUDE_CODE_DISABLE_CRON` | `1` | 定期実行の道具と、`loop` のスキルが消える |
| `DISABLE_AUTOUPDATER` | `1` | 実行の中で、Claude Code が自分を更新しない |

利用枠の見張りの役が Claude の設定ディレクトリを使うときも、`DISABLE_AUTOUPDATER` を足す。今 `CLAUDE_CONFIG_DIR` を足す条件と同じにする。

### バックグラウンドの実行

Multica は、実行の終わりに残った処理を捨てる。今は役の指示とランタイムの決まりで禁じているが、この変数で機能ごと止める。

変数を付けても、`Monitor` の道具は残った。そのため、`Monitor` は設定の `permissions.deny` で止める。deny は、bypass の権限でも効いた。

QA の役は、E2E でアプリを起動する。道具の裏の実行がなくても、起動のコマンドが終わるまで待つか、シェルで切り離して起動できる見込みである。流し直しのあとの E2E で動くことを確認する（[テストと実機の確認](#テストと実機の確認)）。

### バージョンの固定

Claude Code のバージョンは、人間が組織の手順で入れたバージョンに固定する。バージョンを上げるのは、人間の操作だけにする。

このホストの Claude Code は Homebrew で入れたもので、自分では更新せず、`brew upgrade` を案内するだけだった。ほかの入れ方では実行の中で更新することがあるので、変数で止める。`claude update` の手での更新は止めない。

## Codex の設定

エージェント用の `config.toml` に 2 つのキーを足し、役の引数に 1 つの値を足す。セットアップは、`config.toml` を Codex の厳しい検証にかける。

| 置き場 | キー | 値 | 効くこと |
| --- | --- | --- | --- |
| `config.toml` | `check_for_update_on_startup` | `false` | 起動のたびに新しいバージョンを問い合わせない |
| `config.toml` | `[analytics]` の `enabled` | `false` | 利用のデータを送らない |
| 役の引数 | `-c project_doc_max_bytes=65536` | 65536 | 作業ディレクトリの AGENTS.md を、64 KiB まで読む |

キットは、マークのある `config.toml` だけを置き換える。マークのない人の設定に 2 つのキーがないときは、警告を出して先へ進む。`allow_login_shell` と違い、なくてもガードは効くためである。

### 指示を読む量の上限

Multica は、Codex の役の指示とランタイムの決まりを、作業ディレクトリの AGENTS.md に書く。Codex は、既定では 32 KiB を超えた後ろを読まない。

このホストの Codex の作業ディレクトリでは、56 件のうち 8 件が 32 KiB を超えていた。最大は 37,548 バイトで、後ろにはランタイムの結果の返し方などの決まりがある。上限を 64 KiB にすると、今の大きさの倍まで読める。

上限は、`config.toml` ではなく役の引数で渡す。マークのない人の `config.toml` のホストでも効き、古いキットで流し直しても消えないためである。`lib/project.sh` の `project_desired_args` が今 `allow_login_shell` を付け外しするのと同じく、キットが持つ引数として付け外しする。

### 設定の検証

セットアップは、Codex の準備の中で、エージェント用の設定を厳しい検証にかける。知らないキーや形の合わない値があれば、止まって直し方を出す。

| 項目 | 決めたこと |
| --- | --- |
| コマンド | `codex app-server --strict-config --listen stdio://` を、エージェント用の `CODEX_HOME` で、標準入力を閉じて起動する |
| 通る結果 | 終了コード 0 |
| 止まる結果 | 下の 2 つの場合を除く、0 以外。知らないキーがあると 1 で終わり、`unknown configuration field` を出す |
| 古い Codex | 終了コード 2 で、標準エラーに `unexpected argument '--strict-config'` があれば、検証できなかったと警告して先へ進む |
| 時間の上限 | 30 秒。過ぎたら、起動した子のプロセスだけを止め、確認できなかったと警告して先へ進む |
| 置く所 | `allow_login_shell` の確認のあと、ログインの確認の前 |

キットが求める Codex の最低のバージョンは 0.171.0 で、このホストの 0.172.0 より古い。0.171.0 が `--strict-config` を受け付けるかは確認していない。0.172.0 は、知らない引数に終了コード 2 と上の文を返した。そのため、受け付けない Codex では、検証を飛ばして警告する。

`timeout` のコマンドは macOS に標準でないので使わない。`codex features list` などのサブコマンドは、`--strict-config` を付けると端末の画面に入り、正しい設定でも失敗した。

役の引数には `--strict-config` を付けない。Codex のバージョンが上がって設定のキーが変わったとき、役の実行がすべて止まるのを避けるためである。検証は、セットアップを流す人の目の前で行う。

検証の起動は、エージェント用の置き場に状態のファイルを作る。役の実行も同じファイルを使うので、害はない。

## 実機で確認した結果

棚卸しで「要確認」とした項目と、Codex の項目を、このホストで確認した。ホストのバージョンは Claude Code 2.1.322 と codex-cli 0.172.0 である。

Claude Code は、共有の設定ディレクトリを変えずに、`--settings` で同じ値を渡して確認した。設定ディレクトリの `settings.json` でも同じに効くことは、流し直しのあとに人が確認する（[テストと実機の確認](#テストと実機の確認)）。

### 要確認の項目

3 つの要確認のうち 1 つを入れ、2 つを外した。

| 項目 | 実機で確認したこと | 扱い |
| --- | --- | --- |
| AGENTS.md の自動読み込み | 設定では、checkout しているブランチの AGENTS.md が入った。main の AGENTS.md だけを入れるには、フックが要った | 外した。読み込まない値を書き、指示の手順で読む |
| バックグラウンドの実行を切る | Bash の裏の実行が消え、サブエージェントは同期で動いた。`Monitor` は残った | 入れた。`Monitor` は deny で止める |
| 子プロセスから認証情報を外す（`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`） | bypass の指定が既定の権限に戻され、道具の呼び出しが拒否された | 外した |
| Codex のモデルの引退 | ひな形のモデルが、ドキュメントの引退の一覧にないことを照らした | 確認だけ。設定は変えない |

### AGENTS.md の読み込みの確認

作業ディレクトリと同じ形の置き場を作り、4 つの場所に AGENTS.md と CLAUDE.md を置いて、同じ場所のファイルを Read した。読み込む設定は、`instructionFiles` を `claude-md-and-agents-md` にしたものである。

| 場所 | 設定なし | 読み込む設定 | 読み込む設定と `claudeMdExcludes` | CLAUDE.md（今の動作） |
| --- | --- | --- | --- | --- |
| checkout の根 | 入らない | 入った | 入った | 入った |
| checkout の下の階層 | 入らない | 入った | 入らない | 入った |
| 作業ディレクトリの `tmp` の下 | 入らない | 入った | 入らない | 入った |
| 作業ディレクトリの外 | 入らない | 入らない | 入らない | 入らない |

承認済みの main の AGENTS.md だけを読めるかは、main と PR のブランチで違う AGENTS.md を置いたリポジトリで確認した。PR のブランチを checkout し、ほかのファイルを Read した。

| 設定 | 文脈に入った AGENTS.md |
| --- | --- |
| 読み込む設定 | PR のブランチのもの |
| `claude-md` と、Read の後のフック | main のものだけ |
| 読み込む設定と、作業ディレクトリの下の AGENTS.md をすべて飛ばす `claudeMdExcludes` と、フック | main のものだけ |

`instructionFiles` が選べるのは、読み込むファイルの種類だけである。git のどのブランチから読むかは選べないので、設定だけでは main に絞れない。フックは、Read したファイルのリポジトリで `origin/HEAD` が指すブランチの AGENTS.md を `git show` で読み、文脈に足した。Multica の checkout でも、`origin/HEAD` は `origin/main` を指していた。

### 要確認でない項目

ほかの項目も、効くことを実機で確認した。外したものはない。

| 項目 | 実機で確認したこと |
| --- | --- |
| claude.ai の同期を切る | `anthropic-skills:` で始まるスキルが、一覧から消えた |
| `disableWorkflows` | Workflow の道具と、`deep-research`・`workflow-authoring` が消えた |
| `CLAUDE_CODE_DISABLE_CRON` | 定期実行の 3 つの道具と、`loop` が消えた。`ScheduleWakeup` と `RemoteTrigger` は残った |
| `skillOverrides` | 止める 14 件が消え、残す 6 件と共通スキルが残った |
| `permissions.deny` | 書いた道具が、bypass の実行の道具の一覧から消えた |
| `autoMemoryEnabled` | メモリの置き場が、実行に渡されなくなった |

### Codex の項目

Codex の 3 つの値と検証は、どれも入れた。下の階層の AGENTS.md は、Codex では読み込まれなかった。

| 項目 | 実機で確認したこと | 扱い |
| --- | --- | --- |
| `--strict-config` | app-server が受け付け、知らないキーで終了コード 1 になった | 入れた。セットアップの検証だけ |
| 知らない引数 | 終了コード 2 で、`unexpected argument` の文を出した | 古い Codex の見分けに使う |
| 更新の確認と分析を切る | 2 つのキーが、厳しい検証を通った | 入れた |
| AGENTS.md の上限 | 約 35 KB の AGENTS.md の末尾は、既定では読まれず、65536 にすると読まれた | 入れた。役の引数で渡す |
| 下の階層の AGENTS.md | 作業ディレクトリの下の checkout の AGENTS.md は、ファイルを読んでも入らなかった | 変えない。役の指示の手順で読む |

Claude の項目のうち、Codex に同じ設定がないものは足さない。

## 入力と信頼の表

この変更は、役の実行の設定を決める共有のファイルと、役の文脈に入るファイルに触れる。共有のファイルは、同じ OS の利用者で動く役と、その子プロセスも書ける。読む入力ごとに、信頼する条件を次のとおりにする。

| 入力（誰が書いた何か） | 読むところ | 信頼する条件 | 合わないとき |
| --- | --- | --- | --- |
| 共有の `settings.json`（人・キット・役とその子プロセスが書ける） | セットアップの合わせる処理 | 通常のファイルで、最上位とキットのキーの形が合う | 書かずに止まり、直し方を出す |
| 同じファイルの、キットが持つキーの値（人・役とその子プロセスが書ける） | 役の Claude Code の起動 | 流し直しのときに、キットの値と同じ。実行のときは確認しない | 流し直しでキットの値に戻し、警告を出す。実行の間の書き換えは止めない |
| エージェント用の `config.toml`（マークがあればキット、なければ人。役とその子プロセスも書ける） | セットアップの検証と、役の Codex の起動 | `allow_login_shell` が `false` で、厳しい検証を通る | セットアップが止まる。マークのないファイルは上書きしない |
| 役の custom_env と引数（キット・エージェントを編集できるメンバー・CLI を使える役が書ける） | 役の実行の環境変数と引数 | 流し直しのときに、キットの値を含む | 流し直しでキットの値に付け直す。実行の間の書き換えは止めない |
| Codex の検証の終了コードと標準エラー（Codex が返す） | セットアップの判定 | 30 秒の上限の中で終わった値 | 0 以外は止まる。古い Codex と時間切れは、警告して進む |
| checkout と `tmp` の下の AGENTS.md（作業先に push できる人と PR の書き手、添付や ZIP の書き手） | 自動では読まない | なし | `claude-md` の値で読み込まない |

共有のファイルの書き手は、同じ OS の利用者のすべてのプロセスである。権限 600、JSON の形、管理のマークは、書き手の確認にならない。キットは、流し直しのときに値を戻すだけで、実行の間の書き換えを見つけない。この境界は[残る危うさ](#残る危うさ)に書き、人間の承認を受ける。

この変更で、文脈に入る AGENTS.md は増えない。役の指示の手順で読む checkout の AGENTS.md は、この設計では変えず、[残る危うさ](#残る危うさ)に書く。

## 互換性と影響を受ける利用者

共有の設定は、流し直したホストのすべてのプロジェクトの役に効く。設定ディレクトリと Codex の置き場は、ホストで 1 つを共有するためである。環境変数と引数は、流し直したプロジェクトの役にだけ付く。

- 役のスキルの一覧から、人の claude.ai のスキルと、止めた同梱スキルが消える
- 役は、Bash を裏で動かせず、定期実行と `Monitor` を使えない。今の指示は、どれも使わない前提で書いてある
- 役は、今と同じく AGENTS.md を自動では読み込まない。Claude Code の既定が変わっても、読み込まないままになる
- 人がエージェント用のログインの端末を開くと、同じ設定が効く。人が書いたキーは残る
- 人が `settings.json` にキットのキーと別の値を書いていたら、流し直しでキットの値に戻る
- Codex の役は、32 KiB を超える指示の後ろも読むようになる

custom_env、引数、設定は、役の次の実行から効く。デーモンを起動し直す必要はない。

### 新しく止まる場合

今は通るホストで、流し直しが止まる場合がある。止まったときは、直し方を出す。`manual.md` にも同じ内容を書く。

| 止まる場合 | 直し方 |
| --- | --- |
| マークのない人の `config.toml` が、厳しい検証を通らない | 出力の行のキーを直すか消す |
| `settings.json` がシンボリックリンク | 実体のファイルに置き換える |
| `settings.json` が JSON として読めない、または形が違う | 出力の箇所を直す |

### 古いキットとの混在

同じホストに、バージョンの違うキットで流し直すプロジェクトがあると、設定の一部が入れ替わる。キットごとの動作は次のとおりである。

| もの | 古いキットで流し直したとき |
| --- | --- |
| マークのある `config.toml` の 2 つのキー | 古いキットの `host_shared_file` が、中身の違うファイルを置き換えるので消える。新しいキットで流し直すと戻る |
| `settings.json` のキー | 古いキットは書かないので残る |
| custom_env の 3 つの変数と、Codex の引数 | 古いキットは知らない値を消さないので残る |

`config.toml` の 2 つのキーは、更新の確認と分析を切るだけで、ガードには関わらない。入れ替わっても、役の判断は変わらない。同じホストのプロジェクトは、同じバージョンのキットにそろえることを `manual.md` に書く。

### 戻し方

戻すときは、古いキットで流し直したあと、残るものを手で消す。動いているタスクがないときに行う。

1. エージェント用の設定ディレクトリの `settings.json` から、[書くキー](#書くキー)の 8 つを消す。`pluginConfigs`・`skillOverrides`・`permissions.deny` は、キットの項目だけを消す
2. Claude のモデルの役ごとに、`multica agent env get` で今の custom_env を読み、3 つの変数を消したファイルを `multica agent env set --custom-env-file` で書く
3. Codex の役ごとに、`multica agent update --custom-args` で、上限の 2 つの引数を除いた配列を書く

`config.toml` は、古いキットの流し直しで戻る。マークのない人のファイルは、キットが変えていないので戻す作業はない。

## テストと実機の確認

設定を合わせる処理、環境変数、引数は、自動テストで確認する。実際に効くかは、流し直しのあとに人が実機で確認する。

| テスト | 確認すること |
| --- | --- |
| `tests/host-test.sh` | ファイルがないときに、キットのキーだけで作ること |
| `tests/host-test.sh` | 人のキーを残し、`pluginConfigs`・`skillOverrides`・deny の人の項目と混ぜて書くこと |
| `tests/host-test.sh` | キットのキーの人の値を上書きして警告すること。「やめたキー」を消し、キットの項目だけを消すこと |
| `tests/host-test.sh` | 変わらなければ書かず、書くときは権限を 600 にすること |
| `tests/host-test.sh` | シンボリックリンク、壊れた JSON、`permissions`・deny・`pluginConfigs` の形の違いで、書かずに止まること |
| `tests/host-test.sh` | Codex の検証が、0 で進み、0 以外で止まり、古い Codex と時間切れで警告して進むこと。マークのない設定にキーがないとき警告すること |
| `tests/project-create-test.sh`・`tests/project-runtimes-test.sh`・`tests/project-runtimes-first-test.sh` | Claude のモデルの役にだけ 3 つの変数が付き、Codex の役にだけ上限の引数が付き、ランタイムを替えると外れること |

実機では、認証済みのデーモンで、同じプロジェクトのセットアップを流し直してから次を確認する。`--settings` ではなく設定ディレクトリの `settings.json` で効くことを、ここで確認する。戻し方は[戻し方](#戻し方)にある。

1. Claude の役の実行の始めのスキルの一覧に、`anthropic-skills:` で始まるものがない
2. Claude の役の実行の記録で、AGENTS.md でないファイルの Read の結果に、AGENTS.md が添えられていない
3. Claude の役の道具の一覧に `Monitor`・`ScheduleWakeup`・`RemoteTrigger` がなく、実行にメモリの置き場が渡されていない
4. Claude のモデルの役の custom_env に 3 つの変数があり、Codex の役の引数に上限がある
5. 人がエージェント用のログインの端末を開いても、人のキー（`theme` など）が残っている
6. Codex を使うホストで、セットアップの検証が通る
7. QA の役の E2E が、アプリを起動して最後まで流れる

マージの前に人が 1 から 7 を確認し、結果を PR に書く。2 は、AGENTS.md を自分で開く前の Read で見て、指示の手順で読んだものと見分ける。

## 残る危うさ

次の 2 つは、この設計では防がない。人間の承認で、受け入れるかを判断してもらう。

| 危うさ | 範囲 | 防がない理由と、今の守り |
| --- | --- | --- |
| 役やその子プロセスが、共有の `settings.json`・`config.toml` と custom_env を書き換える | 同じホストのすべてのプロジェクトの、次の流し直しまでの役 | 書き手は同じ OS の利用者で、ファイルの権限では分けられない。流し直しで値を戻して警告し、閉じ込めは VM で行う（[VM に閉じ込めて動かす](vm.md)） |
| 役が、役の指示の手順で、checkout の AGENTS.md を PR の未承認の変更ごと読む | PR のブランチを checkout した役。Claude と Codex の両方 | この設計は役の指示を変えないので今の経路が残るが、自動の読み込みは切って経路を増やさない。指示の手順の見直しとフックの形は、順 2 で扱う |

書き換えられるキーのうち、守りに関わるのは `pluginConfigs` と `permissions.deny` である。書き換えられると、AGENTS.md が自動で入り、止めた道具が戻る。どちらも、作業先を広げたり、ガードを外したりはしない。`gh` と `git push` のガードは、共有の設定の外にある。

ほかに、次が残る。

- CLAUDE.md の読み込みは、Claude Code の今の動作のまま、下の階層と `tmp` の下でも入る。この変更では変えない
- 止めるスキルの名前は、Claude Code のバージョンで変わる。バージョンを上げたときに、スキルの一覧を見て、止める一覧を見直す
- 子プロセスから認証情報を外す設定は、bypass と両立しないので入れない。テストやビルドの子プロセスには、今と同じく認証情報が渡る

## 検討した案

設定は共有の `settings.json` に書き、設定のキーにないものだけを環境変数で渡す。全役と再開の実行に、同じ値が確かに効くためである。

| 案 | 選ばなかった理由 |
| --- | --- |
| 役ごとに `--settings` を custom_args で渡す | Multica が再開の実行にも引数を付けるかを、まだ確認していない |
| システムの `managed-settings.json` に書く | 置くのに sudo が要り、人の個人の Claude Code にも効く |
| 環境変数だけで渡す | 同期、AGENTS.md の読み込み、スキルの整理を、環境変数では指定できない |
| `DISABLE_UPDATES` で更新を止める | 人が手で流す `claude update` まで止まる。実行の中の更新を止めれば足りる |
| `disableBundledSkills` で同梱スキルを止める | レビューの役が使うスキルまで消える |
| `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` を入れる | bypass の指定が既定の権限に戻され、無人の実行が道具を使えない |
| 役の引数に `--strict-config` を付ける | Codex のバージョンが上がってキーが変わると、すべての役の実行が止まる |
| Codex の AGENTS.md の上限の話を、導入の文書に書くだけにする | Multica が書く指示が、すでに上限を超えている |
| Codex の上限を `config.toml` だけに書く | マークのない人の設定のホストで効かず、古いキットの流し直しで消える |
| AGENTS.md を自動で読み込み、範囲を checkout の根に絞る | PR の未承認の AGENTS.md を、書き手の確認なしに役の指示へ採用する。範囲の絞り込みも、作業ディレクトリの名前に頼る |
| Read の後のフックで、main の AGENTS.md だけを足す | 実機ではできたが、指示の手順から未承認の変更が入るまま残る。理由は [AGENTS.md の読み込み](#agentsmd-の読み込み)にある |
| `pluginConfigs` を書かず、既定のままにする | Claude Code の既定が変わると、AGENTS.md の読み込みが始まる |
| `PushNotification` も deny に書く | 棚卸しの順 1 のどの項目にも当たらない。外へ知らせる道具の扱いは、順 2 の deny で決める |
| 実行の始めに、共有の設定がキットの値かを確認する | Claude Code は起動のときに設定を読み終えているので、書き換えに気づいても、その実行には効いたあとである。止める仕組みは、順 2 のフックとあわせて決める |
