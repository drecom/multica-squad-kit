# ホストのデーモンの起動入口が答えを読む設計

ホストの起動入口 `common/host/start-daemon` が、答えの保存先からどのファイルを読み、どれを警告して使わないかを書く。使う人への手順は `manual.md` の「PC を起動し直したあと」に、VM の中の起動入口は [docs/vm.md](vm.md) に書く。

## 目的と範囲

目的は、正しいファイルに警告を出さず、本当に使えない答えにだけ、原因に合った警告を出すことである。拡張の記録が毎回警告されると、答えが壊れたときの警告が紛れる。形が合わないだけのファイルに「読めない」と出すと、権限の問題と取り違えやすい。

この文書が決めるのは、次の 3 つである。

1. 拡張の記録を答えとして読まないこと。[拡張の記録を見分ける](#拡張の記録を見分ける)に書く
2. 使わない答えへの警告を、原因で 2 つに分けること。[警告を原因で分ける](#警告を原因で分ける)に書く
3. 新しい警告を `manual.md` に載せないこと。[manual に載せないこと](#manual-に載せないこと)に書く

次は、この文書の範囲の外である。

- 接続先とランタイムを合わせる対象の決まり方。答えを選んだあとの処理は変えない
- セットアップ側の答えの読み取り（`lib/answers.sh` の `latest_answers`）。拡張の記録を黙って飛ばしていて、症状がないため
- `schema` が 2 の答えを読むこと。原本にも履歴にも `schema` 2 の定義がないため
- VM の中の起動入口。答えの保存先を読まないため

## 答えの保存先にあるファイル

答えの保存先は `~/.multica-agent/template/answers/<ワークスペースの ID>/` である。起動入口は、この下の `*.json` を名前の順に見る。ここには、セットアップが書く 3 種類のファイルが並ぶ。

| ファイル | 書く処理 | 起動入口での扱い |
| --- | --- | --- |
| 答え `<プロジェクトのキー>.json` | 質問の処理（`lib/questions.sh`、`lib/answers.sh` の `save_answers`） | 読んで、形を確認して使う |
| 拡張の記録 `<プロジェクトのキー>-<メンバーのキー>.extensions.json` | 拡張の処理（`lib/extensions.sh` の `save_extension_inventory`） | 開かずに飛ばし、警告も出さない |
| 書きかけのファイル `.answers.XXXXXX` と `<拡張の記録>.new` | 同じ 2 つの処理が、置き換える前に書く | `*.json` に当たらないので、見ない。今と同じ |

拡張の記録は、拡張を使わないプロジェクトにもセットアップが書く。置き場所は、[EXTENSIONS.md](../EXTENSIONS.md) が回答の保存先と同じディレクトリと決めているので、変えない。

## 拡張の記録を見分ける

名前が `.extensions.json` で終わるファイルを、開く前に飛ばす。飛ばしたファイルは、接続先を決める最新の判定にも、ランタイムを合わせる対象にも入らない。

答えの名前と重ならないのは、プロジェクトのキーが `^[a-z][a-z0-9]{1,11}$` の形で、点を含まないためである。答えの名前は `<キー>.json` なので、`.extensions.json` で終わることはない。キーの形は、質問の処理の `valid_key` と、セットアップの答えの検査（`load_answers`）が決めている。

この見分け方で、次の 3 つが成り立つ。

1. 正しい答えと拡張の記録が並んでも、決まる接続先とランタイムを合わせる対象は、記録がないときと同じになる
2. 拡張の記録がいちばん新しいファイルでも、最新の判定は答えの中だけで行う
3. 拡張の記録だけがあり、正しい答えがなければ、今までどおり「セットアップが済んでいません」で止まる

### 検討した案

名前で見分ける案を選んだ。ほかの 2 つの案は、次の理由で選ばなかった。

| 案 | 選ばなかった理由 |
| --- | --- |
| 中身で見分ける（`schema` がなく、`roles` と `autopilots` を持つものを記録とする） | 開いて解釈してからでないと決まらない。壊れた記録を、答えと記録のどちらとして警告するかも決められない |
| 答えの名前の形（`<キー>.json`）に合うものだけを読む | 人が手で置いた答えや、別の名前で残った答えを黙って飛ばし、使う答えも変わる。形の合わない答えへの警告も出なくなる |

## 警告を原因で分ける

使わない答えへの警告は、読む手順と形を確認する手順のどちらで落ちたかで、文を分ける。どちらでも、そのファイルを使わずに起動を続ける。正しい答えが 1 つもなければ、今までどおりセットアップを案内して止まる。

1. 読む手順では、ファイルを開き、1 つの JSON の値として解釈する。落ちたら「読めない」の警告を出す
2. 形を確認する手順では、今の検査をそのまま使い、落ちたら「形が合わない」の警告を出す。見るのは、オブジェクトか、`schema`・接続先・ワークスペースの ID・ランタイムの一覧の値である

警告の文は、次の 2 つである。どちらも 1 行で、`注意:` で始まり、末尾にファイルのパスを置く。同じ入口の「別の接続先の答えのファイルは使いません」の警告と、同じ形にそろえるためである。

```text
注意: 答えのファイルを読めないので、使いません: <ファイル>
注意: 答えのファイルの形が合わないので、使いません。不要なら消し、使うなら消してからセットアップを流し直してください: <ファイル>
```

「読めない」の文は、今の文のままにする。直し方を添えるのは「形が合わない」だけにする。読めない原因は権限や書きかけなど様々で、1 つの直し方に決められないためである。

### 2 つの警告の境目

境目は、1 つの JSON の値として解釈できるかである。中身の例ごとに、出る警告を次の表に示す。

| 中身の例 | 出る警告 |
| --- | --- |
| 権限がなく開けない | 読めない |
| JSON の構文が壊れている | 読めない |
| 空のファイル | 読めない |
| JSON の値が 2 つ以上並ぶ | 読めない |
| `null` や配列など、オブジェクトでない | 形が合わない |
| `schema` がない、または 1 でない（`schema` が 2 の古い答えを含む） | 形が合わない |
| 接続先がない、https でない、利用者の情報や問い合わせを含む | 形が合わない |
| ワークスペースの ID がない、ディレクトリの名前と違う | 形が合わない |
| ランタイムの一覧が空、重なる、知らない名前を含む、`null` | 形が合わない |

空のファイルと、値が 2 つ以上並ぶファイルを「読めない」に入れるのは、どちらも 1 つの JSON の文書として解釈できないためである。書きかけや、手で連結した結果に多く、形を直す話ではない。

### 直し方を「消してから流し直す」にする理由

形の合わない答えを残したまま、同じプロジェクトの区別でセットアップを流しても、答えは上書きされない。どちらになるかは、答えがセットアップの検査（`load_answers`）を通るかで分かれる。

| 答えの例 | セットアップの動作 |
| --- | --- |
| `schema` が 1 でない、ランタイムの一覧が空など、検査に落ちる | 「保存済みの答えが不正です」で止まる |
| ワークスペースの ID や接続先だけが今の値と違い、ほかは検査を通る | 止まらず、「そのプロジェクトの区別は別の答えに使われています」と区別を聞き直す |

聞き直されたときに別の区別を入れると、新しい答えが別のファイルにでき、古い答えは残って警告が続く。どちらの場合も、同じ区別で答えを作り直すには、先に消すしかない。そのため、警告の直し方は「使うなら消してから流し直す」の 1 つにする。

起動入口は、答えのファイルも拡張の記録も書き換えず、消さない。原本は人のファイルを消さないので、消すかどうかは人が決める。

## manual に載せないこと

新しい警告は、`manual.md` の「止まったときに見ること」の表に載せない。この表は、止まった表示ごとに確認と再開を書く表で、起動入口の行もすべて止まる場面である。2 つの警告は起動を止めず、「形が合わない」の警告は直し方を文に持つ。

「PC を起動し直したあと」の節も、今の警告を並べていないので変えない。

## テスト

`tests/host-daemon-test.sh` で、要件の場面を確認する。答えの保存先のファイルが実行の前後で変わらないことは、どの場面でも `snapshot` の比較で確認する。開けないファイルの場面でも比べられるよう、`snapshot` の控え方を次の 2 点で変える。

1. すべてのファイルについて、パス・権限・大きさ・更新の時刻を控える
2. 読めるファイルだけ、中身の sha256 も控える。読めないファイルは中身を開かず、1 の値だけで比べる

今の `snapshot` はすべてのファイルの中身を読むので、開けないファイルがあると落ち、場面が失敗する。読めないファイルは起動入口も開けないので、書き換えと削除は 1 の値の変化で見つかる。

- 正しい答えと拡張の記録を同じディレクトリに置き、記録をいちばん新しい時刻にする。標準エラーに記録の名前がなく、決まる接続先と対象が記録のないときと同じことを確認する
- 拡張の記録だけを置き、「セットアップが済んでいません」で止まることを確認する
- 今の形の合わない答えの一覧を、読めない群と形が合わない群に分ける。読めない群は「読めないので」の文だけが、形が合わない群は「形が合わないので」の文と直し方だけが、ファイル名と一緒に出ることを確認する
- 開けないファイルは、権限を外して確認し、場面のあとに権限を戻す。root で流して読めてしまうときは、その場面だけを飛ばす

セットアップの流し直しで、ホストの起動入口が原本のものに置き換わることは、今の `tests/host-test.sh` が確認している。
