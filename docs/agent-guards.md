# 役の実行の仕組みのガード

役の実行で、許していないリポジトリへの `gh` の書き込みと `git push` を、呼び方によらず止める。最後のコメントを書かずに終わる実行は、仕組みで続けさせる。Codex の役にも同じガードを置く。

この文書は、原本を変える人に向けて、ガードの中身と理由、実機で確認した結果を書く。使う人への手順は `manual.md` に書く。

## 目的と範囲

今のガードは、PATH の先頭の `gh` のガードと、git の pre-push フックである。本物の `gh` を絶対パスで呼ぶと `gh` のガードを通らず、`git push --no-verify` は pre-push フックを飛ばす。役の指示の文だけが、この呼び方を止めている。

ここでは、セットアップの流し直しで次の 5 つを入れる。棚卸しで順 2 とした項目のうち、実機で使えたものである。

| 入れるもの | 置き場 | 効く範囲 |
| --- | --- | --- |
| `gh` と git の認証を、許すリポジトリだけに渡す環境変数 | 役の custom_env | 流し直したプロジェクトの、Claude と Codex の役 |
| ツールを呼ぶ前に止めるフック（PreToolUse）と deny のルール | Claude Code の共有の `settings.json` | 同じホストのすべてのプロジェクトの Claude の役 |
| 最後のコメントを確認するフック（Stop） | Claude Code の共有の `settings.json` と、Codex の役の引数 | Claude はホストのすべての役。Codex は流し直したプロジェクトの役 |
| Codex の役の PreToolUse のフック | Codex の役の引数と、エージェント用の `config.toml` の信頼 | 流し直したプロジェクトの Codex の役 |
| リポジトリ側の MCP を読み込まない指定 | Claude の役の MCP の設定 | 流し直したプロジェクトの Claude の役 |

守りの中心は、環境変数の層である。フックはその外し方を止める補助で、同じ OS の利用者のプロセスを完全には閉じ込めない（[残る危うさ](#残る危うさ)）。

次は対象にしない。

- 役ごとに違うガード（「コードを変えない」役の書き込みを止めることなど）。役ごとの設定を渡す口が、今の Multica にない（[要確認の項目](#要確認の項目)）
- 役の指示の手順で読む checkout の AGENTS.md と、その読み方を決めるフック。棚卸しの順 2 の項目にないため、別のタスクで扱う
- サンドボックスと、管理者の設定（`managed-settings.json` と Codex の `requirements.toml`）。棚卸しの順 5 で扱う
- Codex のバックグラウンドの端末を止めること。棚卸しの別の順で扱う
- 役の指示と共通スキルの文。今の決まりの文は残す

## 守りの重ね方

書き込みの経路ごとに、止める層を重ねる。上の層を外しても、下の層で止まるようにする。

| 経路 | 今の守り | 足す守り |
| --- | --- | --- |
| PATH の `gh` | `gh` のガード | なし |
| 本物の `gh` を絶対パスで呼ぶ | 指示の文 | 空の `gh` の設定ディレクトリで未認証にする |
| HTTPS の `git push` | pre-push フック | 認証情報を、許すリポジトリにだけ渡す |
| SSH の `git push` | pre-push フック | SSH のコマンドを包み、許していないリポジトリへの push を止める |
| 上の守りを外すコマンドと設定の書き換え | 指示の文 | PreToolUse のフックで止める |
| 最後のコメントを書かずに終わる | 指示の文 | Stop のフックで続けさせる |

## 認証を許すリポジトリに絞る環境変数

`gh` と git は、役の環境変数から認証の置き場を決める。役の custom_env に次の変数を足し、本物の `gh` と git が人の認証を直接は読まないようにする。custom_env は、Codex の役のシェルのコマンドにも渡ることを実機で確認した。

### gh の認証を分ける

`GH_CONFIG_DIR` に、キットが作る空のディレクトリを渡す。本物の `gh` を絶対パスで呼ぶと、ログインのない状態になり、書き込みは認証の誤りで止まる。

`gh` のガードは、`SQUAD_KIT_GH_CONFIG_DIR` があるときだけ、その値を `GH_CONFIG_DIR` にして本物の `gh` を呼ぶ。PATH の `gh` を使う役とキットのスクリプトは、今と同じく人の認証で動く。`SQUAD_KIT_GH_CONFIG_DIR` は、セットアップを流した人の `gh` の置き場である。

セットアップは、人の置き場を次の順で決める。`gh` 自身が使う順と同じである。

1. セットアップを流した端末の `GH_CONFIG_DIR`
2. `XDG_CONFIG_HOME` の下の `gh`
3. ホームの `.config/gh`

空のディレクトリは、エージェント用の置き場の `guard/gh-empty` に、権限 700 で作る。中にファイルがあれば、セットアップのガードの確認で警告し、消し方を出す。

`GH_TOKEN`・`GITHUB_TOKEN`・`GH_ENTERPRISE_TOKEN`・`GITHUB_ENTERPRISE_TOKEN` がデーモンの環境にあると、空のディレクトリでも `gh` は認証される。セットアップのガードの確認で、この 4 つを見て警告する。

### git の認証情報を絞る

git の設定を環境変数の `GIT_CONFIG_COUNT` と `GIT_CONFIG_KEY_n`・`GIT_CONFIG_VALUE_n` で足す。環境変数の設定は、人とシステムの gitconfig より後に読まれるので、その認証の設定を上書きできる。

| キー | 値 | 効くこと |
| --- | --- | --- |
| `core.hooksPath` | キットの git のフックの置き場 | 今のまま。pre-push のガードを使う |
| `credential.helper` | 空 | 人とシステムの認証情報のヘルパー（`gh auth git-credential`、キーチェーンなど）を外す |
| `credential.https://github.com.helper` | 空 | URL ごとに書いた人のヘルパーも外す |
| `credential.https://github.com.helper` | キットの認証情報のヘルパー | 許すリポジトリにだけ、認証情報を返す |
| `credential.https://github.com.useHttpPath` | `true` | ヘルパーに、リポジトリのパスを渡す |
| `core.sshCommand` | キットの SSH のコマンド | 許していないリポジトリへの SSH の push を止める |

キットの認証情報のヘルパーは、`get` の問い合わせだけに答える。パスの `OWNER/REPO` が、許すリポジトリのファイルにあるときだけ、本物の `gh` の `auth git-credential get` に人の置き場を渡して答えを返す。許すリポジトリの照合は、`gh` のガードと同じにする。

ヘルパーは、親のプロセスをたどり、git の `git-remote-https` から呼ばれたときだけ答える。`git credential fill` で人のトークンを取り出せないようにするためである。どちらかに合わないときは、何も返さずに終わる。git は認証できず、push と fetch が止まる。

許していない非公開のリポジトリは、HTTPS では fetch もできなくなる。役の作業先は許すリポジトリなので、この制約を受け入れる。

### SSH の push を止める

キットの SSH のコマンドは、git が SSH で送るコマンドを読む。`git-receive-pack` で、行き先が `github.com` の許すリポジトリでないときは、止めて理由を出す。ほかのコマンドと許すリポジトリへの push は、本物の `ssh` にそのまま渡す。

git は、SCP の形の URL では `git-receive-pack 'OWNER/REPO.git'` を、`ssh://` の URL では `git-receive-pack '/OWNER/REPO.git'` を送る。どちらの形も、実機の git で確認した。

### 置き場と変数の一覧

ヘルパーとフックのスクリプトは、エージェント用の置き場の `guard/` に置く。PATH には入れない。custom_env には次を足す。

| 変数 | 値 | 付ける役 |
| --- | --- | --- |
| `GH_CONFIG_DIR` | 空のディレクトリ | すべての役 |
| `SQUAD_KIT_GH_CONFIG_DIR` | 人の `gh` の置き場 | すべての役 |
| `GIT_CONFIG_COUNT` | `6` | すべての役。今は `1` |
| `GIT_CONFIG_KEY_1` から `GIT_CONFIG_KEY_5` と値 | 上の表の 2 行目から 6 行目 | すべての役 |

## Claude Code のフックと設定

Claude Code の共有の `settings.json` に、フックと deny のルールを書く。書き方は、キットのキーと項目だけを合わせる今の処理（[役の実行の共有の設定と環境変数](agent-settings.md)）を使う。人が書いたフックと deny の項目は残す。

フックは、`MULTICA_TASK_ID` がない実行では何もせずに通す。人がエージェント用のログインの端末で Claude Code を使うときに、止めないためである。

### 書くキー

キットが持つキーと項目を、次のとおりに足す。

| キー | 値 | 効くこと |
| --- | --- | --- |
| `hooks.PreToolUse` | `Bash`・`Write`・`Edit`・`NotebookEdit` に、キットの PreToolUse のスクリプト | 守りを外すコマンドと書き込みを止める |
| `hooks.Stop` | キットの Stop のスクリプト | 最後のコメントがない終わり方を続けさせる |
| `permissions.deny` | `Read` の人の `gh` の置き場・ホームの `.ssh`・`.git-credentials`・`.netrc` | 認証情報のファイルを、Read で読ませない |
| `permissions.deny` | `PushNotification` | 無人の実行から、外へ知らせる道具を使わせない |
| `permissions.blockWritesOutsideWorkingDirectories` | `true` | Write と Edit で、作業ディレクトリの外を書かせない |

`hooks` の項目は、コマンドのパスで見分ける。キットの置き場のスクリプトを指す項目だけを、キットの項目として合わせる。

### PreToolUse で止めるもの

PreToolUse のスクリプトは、ツールの入力の文字列を読み、次のどれかを含めば終了コード 2 で止める。標準エラーに、止めた理由と、ガードを避けないことを書く。

| 種類 | 含むもの |
| --- | --- |
| 認証の置き場の変数 | `GH_CONFIG_DIR`、`SQUAD_KIT_GH_CONFIG_DIR` とその値、`SQUAD_KIT_ALLOWED_REPOS=`、4 つのトークンの変数 |
| git の守りを外す指定 | `--no-verify`・`core.hooksPath`・`credential.`・`git credential`・`core.sshCommand`・`insteadOf`・`http.extraHeader`・`include.path`・`--config-env` |
| git の環境変数 | `GIT_CONFIG`・`GIT_SSH`・`GIT_ASKPASS`・`SSH_ASKPASS`・`GIT_TRACE` |
| 環境を外すコマンド | `env -i`、`env -u` |
| 認証情報の置き場 | `.config/gh`・`.ssh/`・`.git-credentials`・`.netrc`・`security find-` |
| 読み込まれる設定の書き込み | Write・Edit・NotebookEdit の先が `.claude/settings.json`・`.claude/settings.local.json`・`.mcp.json` |

Bash の入力は文字列の照合なので、書き方を変えればすり抜けられる。このフックは、誤って守りを外すことと、素直な外し方を止めるものである。外されても、環境変数の層が残る。

## 最後のコメントの確認

Stop のスクリプトは、実行を終える前に、その実行がタスクに最後のコメントを書いたかを確認する。Claude と Codex の役で、同じスクリプトを使う。

1. `multica agent tasks` で自分の実行を探し、タスクの ID と始めの時刻を読む
2. タスクがない実行（チャットなど）は、そのまま終わらせる
3. `multica issue comment list` で始めの時刻より後のコメントを読み、書いた実行が自分のものを探す
4. Claude の役は、入力のバックグラウンドの処理と定期実行の一覧が空かも見る
5. どちらかが足りなければ、`decision` を `block` にして理由を返し、実行を続けさせる

CLI が失敗したときは、確認できなかったとして続けさせる。書いたかを読めないまま、終わらせないためである。

続けさせるのは、同じセッションで連続 3 回までにする。4 回目は終わらせ、標準エラーに警告を書く。Codex には回数の上限がなく、Claude Code の上限は 8 回なので、キットが数える。数はセッションの ID ごとにキットの状態の置き場のファイルに書き、確認が通れば消す。

続けさせる理由の文は、最後のコメントをタスクに書くこと、残る処理を終えることを頼む。止めた理由が CLI の失敗なら、その事実も書く。

## Codex のフック

Codex の役にも、PreToolUse と Stop のフックを置く。Codex のコマンドのルールは使わない（[Codex の項目](#codex-の項目)）。

### フックの渡し方

フックは、Codex の役の引数に `-c` で渡す。Multica はタスクごとに Codex の置き場を作り直し、`hooks.json` と `rules/` を写さないためである。`-c` の引数は、再開の実行にも付くことを確認した。

| 引数 | 値 |
| --- | --- |
| `hooks.PreToolUse` | `matcher` を `^(Bash\|shell\|exec_command\|local_shell)$` にし、キットの PreToolUse のスクリプトを呼ぶ |
| `hooks.Stop` | キットの Stop のスクリプトを呼ぶ |

PreToolUse のスクリプトは、Claude と同じ照合を、Codex の入力の形で読む。止める動作も、終了コード 2 と標準エラーで同じにする。

### フックの信頼

Codex は、信頼の記録がないフックを飛ばす。信頼は、エージェント用の `config.toml` の `hooks.state` に、フックごとの `trusted_hash` で書く。タスクごとの置き場は、この `config.toml` を写すので、信頼もタスクに届く。

セットアップは、役と同じ `-c` の引数で app-server を起こし、`hooks/list` でフックの値を読んで書く。値はフックの定義（コマンドのパスと matcher）から決まり、スクリプトの中身は含まない。`config.toml` は、ホストごとに値を埋めて書くファイルになる。

マークのない人の `config.toml` は、今と同じく上書きしない。そのホストでは Codex のフックが動かないので、警告を出す。環境変数の層は Codex の役にも効くので、`gh` と `git push` は止まる。

## リポジトリ側の設定の扱い

役の作業ディレクトリに置かれた設定は、確認なしに役の実行に読み込まれる。読み込まれる場所を絞り、書き込みを止める。

Claude Code が読むのは、作業ディレクトリの直下の `.claude/settings.json` と `.mcp.json` だけである。checkout したリポジトリは作業ディレクトリの下にあるので、その中の設定は読み込まれない。どちらも実機で確認した。

MCP は、Claude の役の MCP の設定を、拡張の MCP がないときも空の `{}` にする。Multica は MCP の設定があると `--strict-mcp-config` を付けるので、`.mcp.json` を読まなくなる。拡張の MCP がある役は、今のまま拡張の設定を渡す。

設定とフックは、PreToolUse のフックで、作業ディレクトリの直下の設定と `.mcp.json` を書かせない。Codex は、信頼していない作業ディレクトリの `.codex` を読まないことを確認したので、足すものはない。

## 実機で確認した結果

棚卸しの順 2 の項目を、このホストで確認した。ホストのバージョンは Claude Code 2.1.322、codex-cli 0.172.0、multica 0.7.0 である。

共有の設定ディレクトリと登録は変えず、作業ディレクトリの下の仮の置き場と `--settings`、仮の `CODEX_HOME` で確認した。Multica の起動の引数とタスクごとの置き場の作り方は、Multica のソースで読んだ。

### 要確認の項目

4 つの要確認のうち 2 つを入れ、2 つを外した。

| 項目 | 実機で確認したこと | 扱い |
| --- | --- | --- |
| 役ごとの設定を渡す（`--settings`、`--setting-sources`） | デーモンの設定のファイルがあると、custom_args の `--settings` は落とされた。`--setting-sources user` は、作業ディレクトリの CLAUDE.md とスキルも読まなくした | 外した |
| 作業ディレクトリの外への書き込みを禁じる | Write と Edit で外への書き込みが止まり、中は書けた。共有の設定ディレクトリの下の記憶の置き場も止まり、Bash は対象外だった | 入れた |
| Codex のフック | 信頼のないフックは飛ばされた。`-c` で渡したフックと `config.toml` の信頼で、`codex exec` の PreToolUse が止め、Stop が続けさせた | 入れた。`-c` の形で渡す |
| 子プロセスへの環境変数（`shell_environment_policy`） | `inherit` を `core` にすると、Multica の認証と許すリポジトリの変数も消えた。Multica はタスクの設定に `inherit='all'` を書く | 外した |

### 要確認でない項目

ほかの項目も、効くことを確認した。外したものはない。

| 項目 | 実機で確認したこと |
| --- | --- |
| PreToolUse のフック | bypass の `-p` の実行で、終了コード 2 のフックが Bash を止め、標準エラーがモデルに渡った |
| deny のルール | Read の deny で、指定したファイルの読み取りが止まった |
| Stop のフック | `block` の応答で、実行が続いた。入力に、バックグラウンドの処理と定期実行の一覧があった |
| リポジトリ側の設定の読み込み | 作業ディレクトリの直下の `.claude/settings.json` のフックと `.mcp.json` は、確認なしに動いた。下の階層のものは読み込まれなかった |
| リポジトリの MCP を止める | `enableAllProjectMcpServers` を `false`、`enabledMcpjsonServers` を空にしても読み込まれた。`disabledMcpjsonServers` の名前と `--strict-mcp-config` では読み込まれなかった |
| 環境変数の層 | 空の `GH_CONFIG_DIR` で、本物の `gh` は終了コード 4 の未認証になった。ヘルパーは、許すリポジトリにだけ認証情報を返し、`ls-remote` が通った |

### Codex の項目

Codex のフックは `-c` の形で入れ、コマンドのルールは外した。フックで同じガードを置けるためである。

| 項目 | 実機で確認したこと | 扱い |
| --- | --- | --- |
| コマンドのルール | `CODEX_HOME` の `rules` は、`git push` と `/usr/bin/git push` を止めた。`bash -c`・`git -C`・`env git` は止めなかった | 外した |
| タスクごとの置き場 | Multica は `config.toml`・`config.json`・`instructions.md` を写し、`auth.json` をリンクする。`hooks.json` と `rules/` は写さない | ルールと `hooks.json` を使わない理由 |
| `hooks.json` と `config.toml` に書くフック | 信頼の記録の鍵に、ファイルのパスが入る。タスクごとに置き場が変わるので、信頼が合わない | 使わない |
| `-c` で渡すフック | 信頼の記録の鍵が、パスによらない。`config.toml` の信頼で動いた | 入れた |
| `-c` で渡す信頼 | 無視された | 使わない |
| 信頼の値 | フックの定義から決まり、スクリプトの中身を変えても変わらなかった | [残る危うさ](#残る危うさ)に書く |
| リポジトリの `.codex/rules` | 信頼していない作業ディレクトリでは、読み込まれなかった | 足すものはない |
| 環境変数の層 | custom_env の変数が、Codex のシェルのコマンドに渡った | 入れた |

## 入力と信頼の表

この変更は、認証情報とガードに触れる。読む入力ごとに、信頼する条件を次のとおりにする。

| 入力（誰が書いた何か） | 読むところ | 信頼する条件 | 合わないとき |
| --- | --- | --- | --- |
| フックの標準入力（Claude Code と Codex が書く。中のコマンドは役が書く） | PreToolUse と Stop のスクリプト | JSON として読め、`MULTICA_TASK_ID` がある実行 | 読めなければ PreToolUse は止める。Stop は確認できなかったとして続けさせる |
| `multica agent tasks` の出力（Multica のサーバーが書く） | Stop のスクリプトの、実行とタスクの照合 | ID が `MULTICA_TASK_ID` と同じ実行 | 見つからなければ、確認できなかったとして続けさせる |
| タスクのコメントの一覧（タスクを読める人と役が書ける） | Stop のスクリプトの、最後のコメントの判定 | 書いた実行の ID が `MULTICA_TASK_ID` で、始めの時刻より後 | 数えずに飛ばし、足りなければ続けさせる |
| Stop の回数のファイル（キットが書く。同じ OS の利用者も書ける） | Stop のスクリプトの上限 | 数字だけの 1 行 | 0 回として数え直す |
| 許すリポジトリのファイル（セットアップが書く。同じ OS の利用者も書ける） | `gh` のガード、ヘルパー、SSH のコマンド | 今の `gh` のガードと同じ形 | 読めなければ、どのリポジトリにも答えず止める |
| ヘルパーの標準入力（git が書く。URL は役が決める） | 認証情報のヘルパー | `github.com` の HTTPS で、パスが許すリポジトリ | 何も返さずに終わる |
| ヘルパーの親のプロセス（同じ OS の利用者のプロセス） | 認証情報のヘルパー | 親をたどって `git-remote-https` がある | 何も返さずに終わる |
| SSH のコマンドの引数（git が書く。URL は役が決める） | SSH のコマンド | `git-receive-pack` なら、`github.com` の許すリポジトリ | 止めて、理由を出す |
| 役の環境変数（キットが custom_env に書く。役も変えられる） | `gh` のガード、`gh`、git | 流し直しのときに、キットの値と同じ。実行の間は PreToolUse の照合だけ | 照合に当たれば止める。当たらない書き換えは止まらない |
| デーモンの環境のトークンの変数（人が書く） | セットアップのガードの確認 | ない | 警告し、消し方を出す |
| 共有の `settings.json` のキットの項目（キット・人・役とその子プロセスが書ける） | 役の Claude Code の起動 | 流し直しのときに、キットの値と同じ | 流し直しでキットの値に戻し、警告を出す |
| エージェント用の `config.toml` の信頼（マークがあればキット。同じ OS の利用者も書ける） | 役の Codex の起動 | `hooks/list` が返した値と同じ | 流し直しで書き直す。マークのない人のファイルは上書きせず、警告する |
| `hooks/list` の値（セットアップが起こした Codex が返す） | 信頼を書くセットアップ | 役と同じ引数で起こし、キットのフックの定義の値 | 書かずに止まり、直し方を出す |
| フックとヘルパーのスクリプト（キットが写す。同じ OS の利用者も書ける） | 役の実行 | 流し直しのときに、原本と同じ中身 | 流し直しで写し直す |
| 作業ディレクトリの直下の `.claude/settings.json` と `.mcp.json`（役とその子プロセスが書ける） | 役の Claude Code の起動 | なし | MCP は `--strict-mcp-config` で読まない。設定はツールでの書き込みを止める |

共有のファイル、スクリプト、環境変数の書き手には、同じ OS の利用者のすべてのプロセスが入る。権限やマークは、書き手の確認にならない。キットは、流し直しのときに値を戻すだけで、実行の間の書き換えを見つけない。この境界は[残る危うさ](#残る危うさ)に書き、人間の承認を受ける。

## 互換性と影響を受ける利用者

環境変数と Codex の引数は、流し直したプロジェクトの役にだけ付く。共有の `settings.json` と `config.toml` は、流し直したホストのすべてのプロジェクトの役に効く。

- 役が本物の `gh` を絶対パスで呼ぶと、未認証で止まる。PATH の `gh` は今と同じく動く
- 役は、許していない非公開のリポジトリを HTTPS で fetch できない
- 役は、作業ディレクトリの外を Write と Edit で書けない。共有の設定ディレクトリの下の記憶のファイルも入り、Bash の書き込みは今のまま
- 役が最後のコメントを書かずに終わろうとすると、3 回まで続けさせられる
- Claude の役は、作業ディレクトリの直下の `.mcp.json` を読み込まない
- 人がエージェント用のログインの端末で使う Claude Code では、フックは何もしない。deny と書き込みの禁止は効く

フックと設定は、役の次の実行から効く。デーモンを起動し直す必要はない。

### 新しく止まる場合

今は通るホストと実行で、止まる場合がある。止まったときは、直し方を出す。`manual.md` にも同じ内容を書く。

| 止まる場合 | 直し方 |
| --- | --- |
| デーモンの環境にトークンの変数がある（警告で進む） | 起動の設定から変数を消し、デーモンを起動し直す |
| 空の `gh` の置き場にファイルがある（警告で進む） | 中のファイルを消す |
| `hooks/list` を読めない、またはキットのフックの値がない | 表示の手順で Codex のバージョンと `config.toml` を直し、流し直す |
| マークのない人の `config.toml` で、Codex のフックが動かない（警告で進む） | キットの `config.toml` に替えるか、表示の信頼の行を人のファイルに足す |
| 人の `gh` の置き場が見つからない | `gh auth login` でログインしてから流し直す |

### 古いキットとの混在

同じホストに、バージョンの違うキットで流し直すプロジェクトがあると、ガードの一部が入れ替わる。キットごとの動作は次のとおりである。

| もの | 古いキットで流し直したとき |
| --- | --- |
| `gh` のガード | 古いものに戻り、新しいキットのプロジェクトの役は PATH の `gh` も未認証になる。止まる側に倒れるので、新しいキットで流し直せば戻る |
| `config.toml` の信頼 | 古いキットが置き換えて消える。新しいキットのプロジェクトの Codex の役は、フックが飛ばされる |
| `settings.json` のフックと deny | 古いキットは知らない項目を消さないので残る |
| custom_env の変数 | 古いキットが `GIT_CONFIG_COUNT` を `1` に戻し、git の認証の指定が外れる。`GH_CONFIG_DIR` は残る |
| `guard/` のスクリプト | 古いキットは消さないので残る |

同じホストのプロジェクトは、同じバージョンのキットにそろえることを `manual.md` に書く。

### 戻し方

戻すときは、古いキットで流し直したあと、残るものを手で消す。動いているタスクがないときに行う。

1. エージェント用の設定ディレクトリの `settings.json` から、キットのフックの項目と、[書くキー](#書くキー)の deny の項目と `blockWritesOutsideWorkingDirectories` を消す
2. 役ごとに、`multica agent env get` で今の custom_env を読み、`GH_CONFIG_DIR`・`SQUAD_KIT_GH_CONFIG_DIR`・`GIT_CONFIG_KEY_1` 以降と値を消したファイルを `multica agent env set --custom-env-file` で書く
3. Codex の役ごとに、`multica agent update --custom-args` で、フックの引数を除いた配列を書く
4. Claude の役ごとに、拡張の MCP がなければ、`multica agent update --mcp-config` で MCP の設定を外す
5. エージェント用の置き場の `guard/` を消す

## テストと実機の確認

スクリプトと設定を合わせる処理、環境変数、引数は、自動テストで確認する。実際に止まるかは、流し直しのあとに人が実機で確認する。

| テスト | 確認すること |
| --- | --- |
| `tests/gh-test.sh` | `SQUAD_KIT_GH_CONFIG_DIR` があるとき、本物の `gh` に人の置き場が渡り、ないとき今と同じに動くこと |
| 足す `tests/guard-git-test.sh` | ヘルパーが、許すリポジトリと `git-remote-https` の親のときだけ答え、ほかは何も返さないこと |
| 足す `tests/guard-git-test.sh` | SSH のコマンドが、2 つの URL の形で、許していないリポジトリへの push を止め、fetch と許すリポジトリを通すこと |
| 足す `tests/guard-hook-test.sh` | PreToolUse のスクリプトが、表の種類ごとに Claude と Codex の入力の形で止め、普通のコマンドを通すこと。`MULTICA_TASK_ID` がなければ通すこと |
| 足す `tests/guard-hook-test.sh` | Stop のスクリプトが、コメントがあれば通し、ないとき・CLI の失敗・残る処理で続けさせ、4 回目で終わらせること。タスクのない実行は通すこと |
| `tests/host-test.sh` | `settings.json` にフックと deny の項目を足し、人の項目を残し、キットの項目だけを付け直すこと |
| `tests/host-test.sh` | `hooks/list` の値で信頼を書き、読めないときに止まり、マークのない人の設定で警告すること |
| `tests/guard-check-test.sh` | トークンの変数と、空の置き場のファイルで警告すること |
| `tests/project-create-test.sh`・`tests/project-runtimes-test.sh`・`tests/project-runtimes-first-test.sh` | 変数とフックの引数と MCP の設定が、役とランタイムに合わせて付き、ランタイムを替えると外れること |

実機では、認証済みのデーモンで、同じプロジェクトのセットアップを流し直してから次を確認する。許していないリポジトリには、書き込みが届かない形で試す。戻し方は[戻し方](#戻し方)にある。

1. Claude と Codex の役で、本物の `gh` を絶対パスで呼ぶ読み取りが、未認証で止まる
2. Claude と Codex の役で、許していないリポジトリへの HTTPS と SSH の `git push --no-verify` が、認証か SSH のコマンドで止まる
3. Claude と Codex の役で、許すリポジトリへの PR の作成と push が通る
4. Claude と Codex の役で、最後のコメントを書かずに終えるよう頼んだ実行が、続けさせられてコメントを書く
5. Claude の役で、作業ディレクトリの直下に置いた `.mcp.json` のサーバーが、道具の一覧に出ない
6. Codex を使うホストで、セットアップが信頼を書き、警告が出ない

マージの前に人が 1 から 6 を確認し、結果を PR に書く。

## 残る危うさ

次は、この設計では防がない。人間の承認で、受け入れるかを判断してもらう。

| 危うさ | 範囲 | 防がない理由と、今の守り |
| --- | --- | --- |
| 役やその子プロセスが、照合をすり抜ける書き方で環境変数を外し、人の認証を読む | 同じホストの役 | 役と人は同じ OS の利用者で、ファイルとプロセスで分けられない。閉じ込めは VM で行う（[VM に閉じ込めて動かす](vm.md)） |
| 役が、Bash で SSH や HTTP の要求を組み立て、人の鍵やトークンで書き込む | 同じホストの役 | 上と同じ。認証情報の置き場を読むコマンドと Read は止める |
| ヘルパーの親のプロセスの名前を偽り、許すリポジトリの認証情報を取り出す | 同じホストの役 | 名前は同じ利用者が作れる。取り出したトークンは人のものなので、ほかのリポジトリにも使える |
| 役やその子プロセスが、フックのスクリプトや共有の設定を書き換える | 同じホストの、次の流し直しまでの役 | Codex の信頼の値はスクリプトの中身を含まない。流し直しで写し直す |
| 役が始めた処理が、再開の前に作業ディレクトリの直下の設定を書く | その作業ディレクトリの再開の実行 | ツールでの書き込みだけを止める。MCP は読み込まない |
| デーモンの環境のトークンの変数 | そのホストのすべての役 | 人が置くもので、キットは消さない。警告を出す |

ほかに、次が残る。

- Bash の書き込みは、作業ディレクトリの外にも届く。`blockWritesOutsideWorkingDirectories` は Write と Edit だけに効く
- Codex の役の Stop は、バックグラウンドの端末を見ない。Codex のフックの入力に、その一覧がない
- フックの照合は、正しい作業の文字列にも当たることがある。当たったら、役は呼ぶ人間に知らせ、照合を直す

## 決まっていないこと

次の 1 つは、実装の中で決める。

| 決まっていないこと | 今決めない理由 | 決める人 | いつまでに | 決まるまでの扱い |
| --- | --- | --- | --- | --- |
| 起こしの確認で、コメントの代わりに `multica issue wakeup checkin` で終える実行を、Stop のスクリプトで見分ける方法 | 実行の一覧とコメントから、checkin を見分ける項目をまだ見つけていない | 実装の役 | マージの前 | 見分けず、上限の 3 回まで続けさせる |

## 検討した案

守りの中心は、認証を許すリポジトリに絞る環境変数にした。役が呼ぶ口によらず、本物の `gh` と git の両方に効くためである。フックは、その外し方を止める補助にした。

| 案 | 選ばなかった理由 |
| --- | --- |
| 役ごとに `--settings` を custom_args で渡す | デーモンの設定のファイルがあると、Multica が落とす |
| `--setting-sources user` で、作業ディレクトリの設定を読まない | 作業ディレクトリの CLAUDE.md とスキルも読まなくなる |
| `shell_environment_policy` で、子プロセスの変数を絞る | Multica の認証と許すリポジトリの変数も消え、Multica がタスクの設定で `all` に戻す |
| `enableAllProjectMcpServers` を `false` にする | `.mcp.json` のサーバーが読み込まれた |
| `disabledMcpjsonServers` に名前を書く | 名前を前もって知る必要があり、リポジトリが名前を変えれば読み込まれる |
| custom_args に `--strict-mcp-config` を足す | MCP の設定を `{}` にすれば、Multica が付ける。引数を二重に持たない |
| Codex のコマンドのルール | タスクごとの置き場に写らない。`bash -c` などの呼び方を止めない |
| Codex の `hooks.json` か `config.toml` にフックを書く | 信頼の鍵にファイルのパスが入り、タスクごとの置き場で合わない |
| Codex の信頼を `-c` で渡す | 無視された |
| Codex の信頼を確認しない指定で動かす | 指定が効かなかった |
| 管理者の設定（`managed-settings.json`、`requirements.toml`）に書く | 置くのに管理者の権限が要り、人の個人の利用にも効く。棚卸しの順 5 で扱う |
| サンドボックスで閉じ込める | 棚卸しの順 5 で扱う |
| 人の gitconfig を書き換えて、認証の設定を外す | 人の端末の git にも効く。環境変数なら役にだけ効く |
| Bash の deny のルールで、コマンドを止める | `sh -c` などですり抜けられる、とドキュメントが書く。フックのほうが照合を書ける |
| Stop を上限なしで続けさせる | Codex には上限がなく、確認できない状態で実行が終わらない |
| `blockReadsOutsideWorkingDirectories` で、外の読み取りも禁じる | 共通スキルと、キットのスクリプトの置き場も読めなくなる。認証情報のファイルは deny で止める |
| 実行の始めに、共有の設定がキットの値かを確認する | 設定は起動のときに読み終えているので、気づいても、その実行には効いたあとである |
