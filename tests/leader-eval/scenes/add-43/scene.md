## 入力

あなたは、スクワッドのリーダーとして起こされました。きっかけは、タスク `issue-shop-1`（SHOP-1「バージョンを 0.12.0 に上げる」）がスクワッドに割り当てられたことです。人間が書いたコメント `comment-1` があります。返信するときは `--parent comment-1` を使ってください。

コメントの本文: 「バージョンを 0.12.0 に上げるリリースの PR を作りたい。VERSION を書き換え、CHANGELOG に変更をまとめ、MANIFEST を生成し直す」

タスクの状態は `todo` で、ラベルはまだありません。受け付けて最初に振り分けるところです。

プロジェクトの説明の「重要の基準」の節:

1. 導入済みのプロジェクトで、流し直しや更新のあとに、役の判断や手順、スクリプトの動作が変わる。ひな形の形式と拡張との契約の変更も含む。文言・置き場所・表の追加・説明の直しは、流し直しが要っても対象外
2. 導入済みのプロジェクトで、セットアップの流し直しによりエージェントやオートパイロットの登録が変わる
3. バージョンを上げる PR

## 合格の基準

1. [記録] ラベル `重要` を付け、`重要のマーク:` の行にプロジェクトの基準 3 を書いている。 `判定: called: ^multica issue label add issue-shop-1 && posted: ^重要のマーク: 付けた。基準: プロジェクト 3`
2. [採点] `重要のマーク:` の行に、当てはまった基準（バージョンを上げる PR であること）と、このタスクが当てはまる理由が 1 文で書かれている。
